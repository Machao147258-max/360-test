## A. 证书完整链（leaf + 中间CA + 根）

脚本 `_recon\chain_builder.py`：从 `certs/der/` 取 46 张证书，按 issuer DN 串链；根证书不在 PKCS#7 里，故用 **Windows 系统 ROOT/CA 存储（ctypes/crypt32 枚举）+ certifi** 补齐。

**输出：`certs\chains\`**
- `*.chain.pem` × 46（leaf→中间CA→根，PEM 顺序拼接）
- `ALL_chains.pem`（全部链合并）
- `_index.txt`（每链：长度 / leaf / root）

结果：**46 条链，43 条补到自签根**（3 条卡在交叉签/旧根，属正常）。

## B. cloudcom2 任务表 = RPC 客户端桩

`cloudcom2.dll` 的导出（`GetFileTrustState`/`MisKillCheckDangerFileSignWhitList`/`CheckStreamTrust`…）本身**不含判定逻辑**，是"薄封装 → 统一分发器 `0x1003cbd0` → `0x1003dd40`/`0x1003dea0`"的 **IPC 客户端桩**，把请求转发给 **deepscan 引擎服务**（`ZhuDongFangYu.exe` / `DSMain.exe`）。

**方法号（RPC method id，十进制）**：
| 导出 | 方法号 | 十六进制 |
|---|---|---|
| `GetFileTrustState` | 300000 | 0x493e0 |
| `GetFileTrustStateWithHandle` | 400000 | 0x61a80 |
| `MisKillCheckDangerFileSignWhitList` | 940000 | 0xe57e0 |

> 真正的"任务表"（id→处理函数）在**引擎服务端**，不在 cloudcom2。（`0x1003cbd0` 里 `taskId+0x3e8/0x44c/0x4b0/0x514` + `push 0x10001` 即构造远程调用。）

## C. 白名单 / 规则库格式 = SQLite

cloudcom2 内 SQL：`SELECT COUNT(*) FROM "FL"` / `FROM "FFQT" WHERE MD=?`（MD=MD5）/ `FROM "NP1"` / `FROM "XD2"`（信任区）→ 白名单/规则是 **SQLite** 表；RTTI：`CWhiteSignale`(单例)、`SignInfoCollecter`、`CDeepScanCache`（XD 表按 MD5+路径+TrustType）。

**安装树里实际存在的库：**

### `libaw.dat`（根目录，1MB，SQLite，反广告/拦截规则库）
| 表 | 行 | 列 | 说明 |
|---|---|---|---|
| `sig` | 1 | id,company,info,enc,mv,result… | `(1,'360','1.0.0.1002',enc=1,…)` → 版本 + **enc=1 表示文本列加密** |
| `adware` | 1054 | id,level,flag,score,**name,company,info**,crc,ratio,boxtext,flag_ext | 广告/流氓签名；文本列为**加密 BLOB** |
| `rrule` | 3759 | id,aid,type,match,remove,rkey,… | 注册表规则 |
| `frule` | 2719 | id,aid,type,match,remove,mp_name,… | 文件规则 |
| `mrule` | 2246 | id,aid,type,match,submatch,remove,… | 模块规则 |

- `adware.name/company/info` 密文：例如 company=`36 d0 b1 8e fd 18 ed 89 66 8e 9d 3a`，其末 6 字节与同行 name 前 6 字节相同 → 密文有共享子串。
- 尝试：单字节/多字节循环 XOR 均**未还原**（UTF-16LE 与 ASCII 打分都不合理）→ 非位移类混淆，应是密钥流/块加密（`enc=1`），未破。

### `cacert.dat`（根目录，246KB）= **155 张 PEM 根证书**
`-----BEGIN CERTIFICATE-----` 明文包；即 `//dsconfig/enablewhiterootcert` 用的**根信任包**（GlobalSign / VeriSign G3 / Entrust / Baltimore / DigiCert Assured ID Root / GeoTrust / AddTrust / QuoVadis / Go Daddy…）。用于"签名链到可信根即放行"。

### `ds*.dat` = 自有格式 **"D063"**
`dsconz/dsbs/dsgs/dsns/dswc/dsws.dat` 头 `44 30 36 33 3c …` = `"D063"` + 版本/条数，高熵 → DeepScan 自有签名库（加密）。
`bifdb.dat` 头 `QHDT` + 版本串 `1.0.0.…`(UTF-16)。

### 运行时下发（不在离线包含）
`libwhite.dat`、`libwhite2.dat`、`Qshield.dat`、`Qshieldz.dat`、`Qshieldzh.dat`、`netconf.dat`、`sndw.dat`、`dscrl.dat`、`dswtb.dat`、`dscon.dat` —— 装后从云端拉取。

**结论**：`libwhite.dat` 的格式 = **SQLite 规则/签名库**，表结构类比 libaw（签名/规则表），关键**文本文列为加密 BLOB（enc=1）**；实际 `libwhite*.dat` 只在运行时下载，离线包里没有。
