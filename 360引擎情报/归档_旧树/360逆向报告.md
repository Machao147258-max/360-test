## 1. 浏览器"霸占"机制

360 包装成 **防劫持/主页修复/浏览器修复**（AntiHijack/HomeRepair/BrowserFix），实为**设主页+锁定+注入插件+改搜索**。

## 2. 代理检测（澄清）

- BrowserFix 的 `_P2SPCheckProxy` **不是**浏览器代理检测——是 P2SP 模块 `GetProcAddress` 表项（同表 `_Run`/`_EnableP2P`…，见 `0x100147fc`）。
- 真正的代理相关：`HomeRepair.dll`/`FileAssoc.exe` 读 `Software\Microsoft\Windows\CurrentVersion\Internet Settings`；`FileAssoc.exe` 有 `(LiveUpdate360) read bad proxy:%d`；`netmon/NetmProxy64.exe`（流量监控）；内核 WFP/DNS 驱动。
- **无单一 `IsProxy()`**，分散在读 IE 系统代理 + netmon 内核流量监控。

## 3. SSL / 证书校验

- `netmon/NetmProxy64.exe`：源码 `.\QHCheckCertificate.c`（头 `…\Interface\QHTL.h`）；内嵌 VeriSign/Symantec/Thawte/GlobalSign CRL/OCSP。
- `safemon/urlproc.dll`（COM）：类 `CHttpsCert`/`C360UrlQueryCert`，protobuf `outchain.info.req.HTTPSCert` —— **把访问站点 HTTPS 证书链上传 360 云**（`chp.f.360.cn/wdcquery`、`cp.uidf.f.360.cn/wpeinfo`）。
- 默认**不做 MITM 解密**；做站点证书链云信誉 + 文件/插件证书校验。根 CA 内嵌（离线可校验）。

## 4. 签名校验：`dynlbase.dll` 的 `SYS_SIGN`

**运行时动态解析 WINTRUST，静态导入表查不到（抗导入分析）**。

### 4.1 初始化 (`fcn.10009832`)
```asm
push u"WINTRUST.DLL"; call LoadLibraryW
GetProcAddress: CryptCATAdminAcquireContext / ReleaseContext / CalcHashFromFileHandle /
                EnumCatalogFromHash / ReleaseCatalogContext / WinVerifyTrust
```
存入结构 [edi+0x08..0x1c]，全局 `0x1010cca8`。

### 4.2 两个入口
- `LuaCheckSysSign` @0x1007bd20：先 `0x1007bc40`（`WinVerifyTrust` + `WINTRUST_ACTION_GENERIC_VERIFY_V2`，`fdwRevocationChecks=2` 整链吊销），失败走 catalog：文件属性（跳过目录、>50MB）→ `CreateFileW` → `CryptCATAdminCalcHashFromFileHandle` → `EnumCatalogFromHash` → `WinVerifyTrust`。
- `LuaCheck360Sign` @0x1007bab0：调 `IsFileSigned` @0x1008c010 → `0x1008bfe4` → `0x1008bf5a` → `0x1008bb73`（自实现内嵌 Authenticode 解析/校验）。返回 `成功 && 结果==1`。

## 5. 云查杀·证书信誉 / 签名白名单（"相同签名→相同结论"）

调用链：
```
CloudEngine.dll (CreateTrustZone/ITrustZone)  +  Cloudsec3.dll
   └─ deepscan/cloudcom2.dll 【实现体】  ← 唯一导出者 (find_exporter 证实)
         imagehlp!ImageGetCertificateHeader/Data  (读 PE 证书表提签名)
```

### 5.1 `cloudcom2.dll` 关键导出
`GetFileTrustState`(0xb8b90)/`Ex/Ex2/WithHandle`、`MisKillJudgeWhite/Ex/OnlyFile`、
**`MisKillCheckDangerFileSignWhitList`**(0xb9180)、`CheckStreamTrust`(0x3d560)、
`AVCacheQuery`/`IsCahceTruested`(拼写原样)、`AVInsertWhite/DeleteWhite`、
`QueryFilesIsFileInXD`/`QueryFilesIsFileMD5InXD`（信任区 XD 表）。
`MisKillCheckDangerFileSignWhitList` → 任务分发器 `0x1003cbd0`（任务号 0xe57e0）。

### 5.2 判定粒度 = 签名者证书
1. `ImageGetCertificate*` 取内嵌签名 → `SignInfoCollecter` 解析 `<sign>`/`<sign_corp>`/`<sign360>`
2. 查签名白名单：`libwhite.dat`/`libwhite2.dat`/`Qshield*.dat`/`bifdb.dat`（命中→该签名者整体可信）
3. 根证书白：`//dsconfig/enablewhiterootcert`
4. 信任区：`CDeepScanCache`（XDITEM 表，按 MD5/路径 + TrustType）
5. 缓存：`AVCacheQuery`/`IsCahceTruested`
6. 云端：`jcloudscan!CloudQueryNetQuery`，头带 `x-360-md5`/`x-360-sign`，回 `TrojanName`/`QvmInfoScore`/`QvmInfoLevel`/`SoftClass`/`NetLevel`（protobuf `cloudquery.pb`）

**结论**：扫描遇"相同签名"= 按**签名者证书**命中白名单/根证书白/信任区之一 → **整批放行**，并进缓存。→ 信任绑在签名者上（同一被信任厂商签的所有文件同等放行）。

配置开关（cloudcom2 字符串）：`//dsconfig/enablewhiterootcert`、`enablewhitesignale`、`enabledangerwhitesignale`、`enableigexpsign`、`judgeinvalid`、`bcerts/cert`(黑证书)。
